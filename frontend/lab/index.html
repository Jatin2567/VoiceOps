THE FIELD GUIDE
Know what
you measured.


Architecture, precisely.
All five modes use recorded-turn Groq Whisper transcription and the same Groq reasoning model, prompt and tools. Buffered holds the complete response; streaming sends sentence-level speech as it becomes available. Guarded adds deterministic checks to sandbox actions. Two intermediate modes hold only text or only audio so each buffering choice can be compared independently.
This compares orchestration and delivery. It does not compare native speech-to-speech, continuous transcription, or native speech-to-speech. Conversation supports cancelling a reply when speech is detected; the controlled comparison remains one recorded turn per trial.


Read the clock correctly.
Server first audio measures pipeline start to the first PCM frame. Browser first playback measures the client trial-ready signal to the first scheduled AudioContext sample. A streaming buffer adds a small playback lead. Neither measures acoustic output at your speaker. Reports separately record first packet receipt, scheduling lead, scheduled gaps, input endpoint detection, upload/admission round trip, and browser output-latency estimates when available.
STT, first LLM text token, TTS first audio and tool checks have separate observed timestamps. These stages can overlap; do not add them as if they form a single serial total. Missing measurements stay blank.


Make a fair comparison.
Input hashes verify identical WAV bytes across trials. Prompts, provider model names, task settings and results are exported. Each run starts fresh context. Run order rotates each repetition; provider caching, network traffic and free-host warm-up are uncontrolled.
Median and nearest-rank p95 use completed samples with measured playback. Counts and failed trials are shown. p95 is withheld until 20 measured samples; smaller sets show medians only. Paired differences match the same input hash and repetition. Bootstrap intervals require at least five pairs and remain exploratory. Repeat and export across sessions for stronger evidence.


Correctness and policy.
Task samples provide checks for required facts, JSON extraction fields, and exact tool outcomes. Custom expected results are supported. These deterministic checks complement human review; they do not establish semantic correctness. In action tasks the model calls a sandbox tool; guarded mode checks the action allowlist and amount limit. Model compliance can make all modes return the same result. A faster response is useful only if it meets the task.
Tool simulations have no external effects. Timing the policy measures local evaluation, not the model’s full tool round trip. Groq and Edge-TTS are live external services.


Failures are evidence.
Each run has a 60-second pipeline deadline. Two experiments can run at once; each supports up to 30 repetitions per selected mode, plus optional excluded warm-ups. Disconnecting stops active work. Audio stays in tab memory. Reports can be saved locally by explicit choice. Shared daily trial budgets and start-rate limits apply; reservations include failed and cancelled work and may reset on ephemeral hosting redeploys.
Free Render hosting can sleep. If the channel fails, reload and retry. Microphone permissions require HTTPS; use Chrome or Edge if the in-app browser does not grant access. The Conversation workspace supports general tasks, completed-turn context and speech interruption. Headphones help prevent speaker echo from triggering interruption. The legacy booking demo remains available at /studio/.


Reproduce and inspect.
Export JSON for configuration, input SHA-256, per-run events, provider models, responses and playback measurements. CSV gives one row per trial. Comparison rows use one shared server-time scale and preserve overlapping stages. Event details show observed timestamps, not invented stage boundaries. Blind replay hides names but is not a blinded scientific study. The versioned eight-case evaluation suite groups observations by task and architecture.
Tests verify buffering, packet delivery, stage order, tool policy and experiment validation. Live results are observations from the current run, never illustrative numbers.
